## 2. 每项功能的验收记录格式

每次使用不含私人数据的样例，记录：版本/提交、日期、Windows/Python、QQ 后台/浏览器版本、功能编号、电脑前置设置、手机原始操作、预期反馈、实际反馈、手机是否能打开附件、证据位置、结论。失败时写明停在哪一步，修复后重新记录，避免覆盖历史失败。

## 3. 按用户流程执行

| 验收编号 | 操作 | 通过条件 / 当前缺口 |
|---|---|---|
| A01 干净安装 | 新 Windows 用户从源码 ZIP 解压，按手册安装 Python、读取组件、QQ 后台；不复制开发电脑 `.runtime` | 只看文档可完成计算器本机结果、扫码、手机菜单和 `84`；待独立执行 |
| A02 全部菜单 | 手机开菜单，逐页工具、AI、文件、任务、帮助，返回原对话；测试失效选择和数字工作输入 | 不选错对象，不吞掉后续工作输入；已有自动检查与部分真实 QQ 记录 |
| A03 自建程序 | 登记一个普通 Python、一个 input/getpass 示例、一个本机命令行工具；正确解释器/参数/编码 | 每项都能运行，交互逐条返回，本机秘密不出现在 QQ；真实新用户自建流程待补 |
| A04 文件读写 | 手机发小 TXT 和 PNG，返回后再上传同内容，生成报告并取回原件 | 手机实际收到、可打开、电脑与原件内容一致；既有手机实测通过 |
| A05 格式矩阵 | 分别发文字 PDF、混合扫描页 PDF、DOCX 表格、XLSX 缺缓存公式、XLS、PPTX、RTF、HTML、不同编码文本 | 可读内容/页码/行号与缺失警告正确；扫描页不虚构、宏不执行；本机样本通过，整套手机联合验证待补 |
| A06 API 多模型 | 每个计划宣传兼容的服务逐个连接，普通首问/追问、新会话隔离、停止、重开补密钥 | 不沿用错误平台密钥，模型和接口真可用；已验证一个真实配置，其他模型不能据此打勾 |
| A07 AI 工具 | 开启 AI 工具和指定程序授权，手机要求读文件、计算、生成并回传 TXT；再撤销权限 | 有真实工具回执与子任务，附件内容正确，撤销后拒绝新操作；已做代表场景实测与边界检查 |
| A08 项目改动 | 只用可丢弃项目，记录初始文件哈希，手机要求修改并测试导出，核对只读测试 | 实际源码变化，固定测试真实通过，diff/TXT/ZIP 均可打开，未包含私有配置；代表项目手机通过，任意项目不保证 |
| A09 网页新建 | 按图文步骤手动安装扩展、点击连接；QQ 新建，首问中性编号，前台留空白页，再问上一答复编号 | 两次手机收到相同正确编号，第二问不提供答案；本机 Edge 已通过；新用户安装、Chrome 待补 |
| A10 网页旧聊天与故障 | 在电脑先打开中性旧聊天；手机从列表选中后追问；另测未发送草稿/生成中/断开/刷新 | 旧上下文正确，不错发到其他聊天，不覆盖草稿，不确定不重发；异常分支有自动检查，手机旧聊整链路待补 |
| A11 Codex 原会话 | QQ 选择接管后读取中性文件并回传；另用隔离操作测确认/拒绝与取消 | 文件读取与文字返回已由用户确认；实际项目改动、单次确认/拒绝与停止只影响本轮仍需分别记录 |
| A12 Codex 新建 | 手机选择已有隔离项目、模型，确认新建，再读中性文件；另核对模型/项目切换 | 新建后读取文件与文字返回已由用户确认；不同模型/项目选择及更广异常分支仍需分别记录，不能由一次成功全部打勾 |
| A13 队列与重开 | 两个任务占满，第三项排队；看结果、取消；保存工作后重开面板 | 菜单不阻塞，不误停其他任务；旧任务中断、不自动重跑/重发；API 内存对话不恢复应有明确预期 |
| A14 容量与运行条件 | 接近/超过传输和解析限制样本，接收目录容量；另测锁屏、浏览器后台、断网恢复和长时间运行 | 超限明确报错，不把部分读取当全文；已发送不自动重放；边界有本机检查，大文件与长期真人测试待补 |

不能为了完成 A11 而退出仍在执行工作的主 Codex 会话；应另找已保存且可交接的测试会话，并由用户完成必要账号/授权操作。访问真实服务可能有额度消耗，使用中性最小输入，不把生产文件作为测试样例。
