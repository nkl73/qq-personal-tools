# 发布前全功能测试报告

日期：2026-10-25；版本：v0.9.0 预览源码（含本轮 Codex 修复）。

## 结论

按现有 21 类功能逐项检查，当前 Windows 主机下的核心流程通过。修复后全套 **147 项自动检查通过，111.917 秒，无跳过项**；浏览器 9 个 DOM 和 4 个工作器情景包含在其中，不另外相加。干净目录/新虚拟环境的依赖、可选读取器、本机计算、扩展生成与 QQ 后台重新下载安装通过；修复模块另在该虚拟环境重跑 24 项，通过。

真实服务使用当前已配置的 deepseek-flash、Codex 的 gpt-6-astra（恢复测试会话）和 gpt-6.1-sol（新建选择），以及已登录的 Edge/Chrome ChatGPT 网页。没有将其他服务、所有模型、其他电脑或长期稳定性写成已验证。

QQ 入口是已连接的个人账号会话，不是固定的设备传输助手。多数本轮输入由本机通过 QQ 私聊 API 发送，再经真实 QQ 回调进入面板；这验证真实网络链路，不冒充手机人工点击。用户单独确认四份格式/工具 TXT 均在手机收到并可打开。50 MiB 文件的接收和发送有后台及内容证据，没有声称手机已下载该大文件。

## 本轮发现并修复的问题

1. **Codex 独立进程没有继承 Windows 系统代理。** 复现为接口不断重连/请求超时；同一测试会话按现有系统代理启动后真实回复成功。修复只为子进程继承已配置的 HTTP/HTTPS 代理，尊重显式环境代理，回环地址不走代理，不修改系统设置；增加回归检查，并转发不含服务原始正文的重连提示。
2. **新建 Codex 首条消息被空历史查询拦住。** 新建后 `thread/turns/list` 返回尚未 materialized，原流程失败。只对“首条消息前没有历史”的明确接口错误按空历史处理，其他错误仍抛出；增加首条消息/其他错误回归检查，并在真实 QQ 项目与模型选择后复测通过。

额外复核 Chrome 已有聊天的纯后台答复，在另一个空白页保持前台时成功回传（18.02 秒）；未仅凭切回网页后看到结果就把后台行为记为通过。安装指引补充了从工具栏拼图打开扩展弹窗，避免在管理详情页寻找连接按钮。

## 证据与限制

- 自动检查用实际本机进程、HTTP、SQLite 和模拟外部服务；本轮真实模型/QQ/浏览器步骤另有本机记录，二者分开。
- 全套日志及带时间的原始验收状态保存在本机 `.runtime`，含环境数据，不进入源码包；本文是公开用的范围摘要。
- API AI 项目工具本轮在隔离报价项目增加源码注释和 README 标记，8 项既有测试通过；Codex 则在另一个隔离项目将错误减法改为加法并运行只读测试。两者没有改业务项目或桥接开发源码来模拟业务验收。
- 任务数量、权限/路径边界、超时、其他联系人/群聊忽略和恢复不重跑均有对应检查；“取消”不代表撤销之前已经发生的写入。
- 尚未做另一台新电脑/新 Windows 用户的独立安装、所有模型/所有文档布局，以及 24 小时以上长期/睡眠后恢复测试。这些是环境/稳定性验证范围，不能因本轮功能通过而打勾。
- 锁屏测试由用户本轮明确选择跳过，不计为失败，也不计为通过。
- 当前 API 密钥按设计只在内存；本轮重开后需要电脑补填，未替用户改为持久保存。QQ 后台与 Chrome 扩展已连接，最终恢复的是新版面板。
