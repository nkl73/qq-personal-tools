# 单脚本兼容模式

**用手机 QQ，为电脑上的交互式 Python 脚本提供输入，并接收输出。**

A lightweight, local bridge between QQ's phone-transfer conversation and an existing interactive Python script. No LLM provider required.

状态：**v0.1.0 公开预览准备版**。面向 Windows 10/11 x64，Python 3.10+（需要 tkinter）。QQ 收发通过本机 OneBot v11；便携 QQ 组件单独从上游下载。

## 适合什么场景

- 出门后继续操作自己电脑上的多轮 Python 小工具。
- 给已有 `input()` 脚本加一个手机输入入口，不必改写成聊天机器人插件。
- 通过手机查看脚本在每一项输入之后给出的结果。
- 使用自己的模型脚本、资料处理脚本或计算脚本；桥接不替你选择模型，也不要求购买模型 API。

消息流：`手机当前已连接的 QQ 个人账号会话 → 本机 QQ / OneBot → 输入队列 → Python 子进程 → 输出 → 手机`。

默认只处理同一账号自己的个人私聊通道里的 `/py` 纯文字，忽略其他联系人、群聊和程序自己的回复。正常收发不点击聊天窗口、不模拟键盘，也不依赖桌面助手。

## 5 分钟试用

1. 安装 Python 3.10 或更新版本，安装时包含 tkinter。下载或克隆本仓库，解压到可写目录。
2. 双击 `安装后台组件.cmd`。安装器只从 NapCat 官方 GitHub release 下载固定版本，并校验 SHA256；**不修改系统 QQ 安装目录**。
3. 普通电脑 QQ 退出登录。运行 `启动单脚本.cmd` 或 `python app.pyw`。
4. 点击“QQ 登录 / 刷新二维码”，手机 QQ 扫码并确认。二维码过期时关闭二维码页，再点击刷新。
5. 保留默认 `examples/echo.py`，点击“启动脚本桥接”。在手机 QQ 中当前已连接的个人账号会话发送 `/py 你好`，应收到 `收到：你好`。

默认示例不需要密钥、不调用模型、不运行终端命令。只有首次设置和需要本机隐私输入时才要打开控制面板，正常运行可最小化。

已运行自己的 NapCat / OneBot？取消“由桥接启动便携后台 QQ”，点“QQ 连接设置”。按 [连接说明](onebot.md) 配置即可，无需再装便携组件。

## 接入自己的脚本

在面板里选择：

| 设置 | 用途 |
|---|---|
| Python 脚本 | 你信任且希望桥接的 `.py` 文件 |
| Python 解释器 | 目标脚本所在虚拟环境的 Python；需要的依赖在该环境安装 |
| 工作目录 | 留空时使用脚本目录 |
| 程序参数 | 每行一个参数；包含空格的参数也直接写一整行 |
| 消息前缀 | 默认 `/py`，可改成 `/run` 等 |
| 单轮等待 | 从一次输入到下一个提示 / 程序结束的超时，默认 300 秒 |

例如脚本：

```python
name = input("你的名字：")
print(f"你好，{name}")
```

手机收到“你的名字：”后回复 `/py 小明`。单独 `/py` 表示空输入。参数通过参数列表传递，不经过 shell；QQ 文字不会作为命令启动。输入时的前后空白会被移除。

也可以预选路径：

```text
python app.pyw --target "C:/scripts/my_tool.py" --python "C:/envs/my_tool/Scripts/python.exe"
```

脚本结束后，发送 `/py /启动` 或 `/py /restart` 重新运行。停止或关闭控制面板会停止目标子进程；已启动的 QQ 后台组件继续在线。

## 隐私输入

脚本调用 `getpass.getpass()` 时，手机只收到“等待本机隐私输入”的提示。请在电脑面板输入当前值；不同的 `getpass()` 提示分别填写，不自动复用上一项。

桥接不会把这些值写入设置或 QQ 队列，并在目标输出中遮盖已通过该面板提交的原始值。这不是通用敏感信息识别：编码、变形后的密钥，以及脚本自己从环境或文件读取的秘密，仍需目标脚本自行保护。

## 支持边界

| 支持 | 首版不支持 |
|---|---|
| `input()` / `print()` 多轮交互 | 接管已经开着的 VS Code 终端 |
| 本机 `getpass()`、脚本参数、自选 Python 和工作目录 | `curses`、全屏 TUI、依赖真实 TTY 的程序 |
| 本机登录账号自己的个人会话 | 群聊、多个用户共享会话、其他 IM 平台 |
| 按提示输出与程序结束回传 | 按字符实时直播输出、图片和文件回传 |

不会把 `sys.stdin.readline()`、原生扩展直接写标准输出、`os.read()`、子进程交互等所有输入输出形式自动转换成提示。请先用简单脚本验证。目标脚本以当前系统用户的权限运行，**没有执行沙箱**，只选择自己信任的代码。

电脑须开机联网且不能睡眠；普通电脑 QQ 与便携实例不能同时登录同一账号。此通道有第三方 QQ 实现依赖，可能遇到登录失效、账号限制或协议变化；这不是腾讯官方机器人接口。

## 可靠性与本地数据

消息编号去重、发送回执核实、长回复分段、回调签名校验和本机地址限制均默认启用。发送结果不确定时保存在 `.runtime/未确认后台回传-编号.txt`，不会自动重复发送。桥接重启后不会回放旧输入、旧提示。登录账号变化时会暂停。

`.runtime/` 包含设置、QQ 登录状态、连接令牌、消息与输出；`.napcat/` 是下载的后台组件。它们已被 Git 忽略，**不要把它们放进 Issue、截图或手动上传的 ZIP**。项目无遥测或自动上传诊断功能。

当前 15 项本地检查覆盖普通输入、多轮提示、独立本机隐私输入、自选解释器与参数、工作目录、超时、回调签名、HTTP 分块传输、防重发和完整回调 / 队列 / 输出流程。检查不需要 QQ 账号或 API Key。

已提供 Windows / Ubuntu、Python 3.10 / 3.12 / 3.13 的 GitHub Actions 配置；有配置不代表这些环境已经验证。真实手机往返在本项目通用化之前已通过，通用预览版需要更多机器试用。见 [贡献说明](../CONTRIBUTING.md) 和 [变更记录](../CHANGELOG.md)。
