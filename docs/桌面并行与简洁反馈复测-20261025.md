# 桌面并行与简洁反馈复测

日期：2026-10-25。针对“桌面应用必须关闭”和“QQ 过程消息过多”两项反馈，修订本机预览源码，尚未发布 GitHub。

## 结果与用法

- 桌面应用可以保持打开。新建独立对话和未被占用的其他聊天可继续工作；同一原聊天仍受写入连接限制。
- `/py codex` 选已有会话后可选“建立手机分支”；遇到占用后可明确选“开手机分支并处理刚才要求”。保留已保存上下文和原模型，不自动分支、不重复提交。分支历史不自动合并，项目文件共用。
- QQ 默认只发最终结果、文件、必要提问、授权和失败。接受回执、工具步骤、重复等待提示及结束时的历史重播不再默认发送。Codex 的中间说明与最终答复分开处理；API 工具调用过程留在电脑。
- `/py 消息` 按编号选简洁或详细；任务菜单分别看“文字结果”和“执行详情”。多个活跃任务时回复注明归属。普通程序的最终输出仍由该程序自己决定，桥接不能可靠猜测它打印的哪些行是业务结果。

## 真实本机与 QQ 验证

使用隔离项目和两个独立的官方本地 app-server 连接，测试期间当前桌面应用一直运行。

| 检查 | 实际观察 |
|---|---|
| 保留原写入连接 | 原连接创建只读测试聊天，保存随机编号后保持连接打开 |
| 原聊天占用 | 第二连接恢复该聊天时出现 active writer；没有提交要求或关闭原连接 |
| 明确选择分支 | 选择分支后只向新聊天提交一次要求，能回答原聊天保存的随机编号 |
| 模型与权限 | 发现直接 fork 会回到服务器默认模型，已修复为显式传入保存的模型/提供方/推理强度；真实复测 gpt-6.1-sol、on-request、readOnly、目录和 xhigh 与来源一致 |
| 原聊天与文件 | 原聊天最后轮次未变化，测试项目文件未改动 |
| QQ 发送 | 真实后台接口接受分支结果并返回发送凭据；回复使用短前缀，不附带随机消息哈希 |

本轮新流程未再要求用户在手机点击菜单和确认，因此不把电脑侧真实发送凭据写成新的手机人工验收。既有手机验收仍见[全功能测试报告](全功能测试报告-20261025.md)。

## 自动回归

完整 **158 项检查通过，117.289 秒，无跳过**。其中新增 11 项回归覆盖手机分支的明确选择、占用后单次提交、原任务不被中断、保存模型继承、最终答复阶段筛选、API 工具步骤留在电脑、授权仍完整送达、交互脚本结束不重播、简洁/详细切换保存、旧数据库升级、回复以 `/py` 开头时的防回环。浏览器 DOM 与后台工作器检查亦包含在本次全套运行中。

## 尚未改变的边界

手机分支只含已保存历史，不包含桌面未保存草稿、进行中工具的临时状态；不承诺两边同时修改同一文件不会冲突，也不提供分支历史自动合并。Codex 桌面专属工具仍可能需要回电脑处理。锁屏、睡眠恢复、跨机和长期运行维持原验收状态，本轮没有补验。

隔离测试期间未重启用户仍在等待输入的旧 API 会话。随后用户明确选择“现在结束这段对话，帮我重开新版”，已结束旧进程并重开新版，QQ 后台登录沿用。实际 QQ 发送计算指令，经真实回调执行后仅发送一条结果 `84`；接受回执保留在本机，没有额外任务创建/进度/等待消息。旧 API 会话记录标为中断，不自动重跑；未选择记住的密钥需在电脑补填。
