# 本机 OneBot v11 连接

桥接既可以管理便携 NapCat，也可以连接你已运行的本机 OneBot 实现。个人私聊消息的事件行为需要与 NapCat 兼容；不能据此保证所有 OneBot 实现都支持此通道。

## 聊天入口与接收范围

当前实测入口是已连接的 QQ 个人账号会话，显示的可以是账号昵称，不要求名称为“我的电脑”或“我的手机”。在该个人账号聊天发送 `/py 菜单`，收到回复后再运行工作。

代码接收本机登录账号自己的私聊消息：文本与文件事件都要求 `self_id`、`user_id` 对应登录账号，事件提供 `target_id` 时也要对应同一账号；回复使用该账号的私聊发送接口。它不以聊天标题或设备名称判断来源，不能由此推定允许另一个好友或群聊控制。配对后聊天的真实账号信息不属于公开文档内容。

## 连接已有实例

1. 在桥接面板取消“由桥接启动便携后台 QQ”。
2. 停止桥接后打开“QQ 连接设置”，填写 OneBot 的本机 HTTP 服务地址、事件接收端口和随机 Token。Token 至少 24 字符；地址仅允许 HTTP loopback，例如 `http://127.0.0.1:18768`。
3. 在 OneBot 组件中启用 HTTP 服务，填入相同 Token。
4. 启用 HTTP 客户端，回调设为 `http://127.0.0.1:18767/events`（端口与桥接设置一致）。消息格式选 array，启用 `reportSelfMessage` / 自身消息上报，填入同一 Token。
5. 完成 QQ 登录，再启动脚本桥接。

回调校验 `x-self-id` 及 `x-signature: sha1=<HMAC-SHA1>`；只有登录账号自己的私聊、当前监听期间的新 `/py` 文字指令会进入队列。回调接受 Content-Length 或受长度限制的 HTTP chunked body。

## 默认端口

| 端口 | 用途 |
|---|---|
| 18766 | 桥接内部输入队列，单实例 |
| 18767 | OneBot 发到桥接的事件 |
| 18768 | OneBot HTTP API |
| 18769 | 托管 NapCat 本机管理界面 |
| 18770 | 可选 ChatGPT 网页扩展的本机配对队列 |

均只绑定 / 连接本机。不要把这些端口直接开放到公网。本机连接令牌不等于 QQ 密码，也不等于任何模型 API Key。

托管模式会生成 `.runtime/napcat-state/config/onebot11.json`，以及已登录账号对应的配置文件。修改托管连接设置后，下一次启动桥接会重启由它管理的后台组件来加载设置；其他 QQ / Node 进程不会被停止。外部 OneBot 的配置和生命周期由你自己管理。

## 常见问题

- **发得出、收不到**：确认 HTTP 客户端、自身消息上报、回调端口、签名 Token 均正确，并确认测试使用当前已连接的 QQ 个人账号会话会话。
- **同一账号已经登录**：退出普通电脑 QQ 的登录，再扫码。仅关闭聊天窗口不一定退出登录。
- **等待隐私输入**：从任务栏打开电脑面板填写；不要把秘密发到 QQ。
- **交互脚本没有新提示**：它按 `input()` / `getpass()` 或退出分轮回传；普通任务有主动刷新输出时会发送限频进度，没有输出时不会生成进度。检查程序是否属于支持范围。
- **发送回执不确定**：查看 `.runtime/未确认后台回传-编号.txt`，先核实手机消息，再决定是否重发。
- **日志太多或准备提 Issue**：只提交脱敏后的错误描述，不上传整个 `.runtime/`。
