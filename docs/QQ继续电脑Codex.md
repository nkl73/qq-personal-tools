# 在 QQ 继续电脑上已登录的 Codex

手机可以沿用电脑官方 Codex 的已有登录、项目和已保存会话继续工作。无需在桥接里填写 OpenAI API Key，也不使用“添加 AI”里登记的其他模型。

**2026-10-25 本轮复测：继续/新建读文件、隔离项目修复并测试、单次同意/拒绝和取消均通过。** 此前用户已确认两种会话方式均可读文件并返回文字。本轮桌面应用保持打开，桥接使用未被桌面占用的测试会话；同一原会话的写入权限制不变。见[本轮测试报告](全功能测试报告-20261025.md)。

## 手机操作

桌面应用可以保持打开。首页 Codex 菜单可新建独立对话；选已有会话后还可建立“手机分支”，保留已保存上下文。分支使用原会话已保存的模型、模型提供方和推理强度，项目与权限由原会话继承，不悄悄切到服务器默认模型。创建分支或独立对话本身不调用模型，发送工作要求才开始处理。

手机分支的聊天记录不自动合并回原聊天；项目文件仍是同一份，避免两边同时修改同一个文件。分支是用户明确选择后的独立聊天，不是让同一原聊天接受两个写入连接。

也可发送 `/py 菜单`，选“继续电脑 Codex”；后续会话、继续、重试与授权都按当前提示回复 `/py 序号`。实际工作要求再用文字描述，无需记住命令词。

1. 电脑先安装并登录官方 Codex，打开过要继续的项目会话。保持电脑开机联网及桥接面板运行；桌面应用可以保持打开。
2. QQ 中当前已连接的个人账号会话发送 `/py codex`，也可用 `/py 运行 codex`。
3. 没有本机默认会话时，回复列表序号或完整会话编号。可回复“查找 关键词”搜索、“下一页”翻页。
4. 按提示选“继续原会话”或“建立手机分支”。原会话被占用时，选分支即可保留上下文继续；若已提交要求遇到占用，菜单会明确询问是否建立分支处理刚才要求，不会自动重发或分支。
5. 发送 `/py 你的工作要求`，例如 `/py 检查当前项目的测试失败原因，修复后告诉我改动和验证结果`。

选中后可继续多轮对话，模型与项目设置沿用原会话。仅选择和交接不会发起模型生成。需要确认的命令、文件改动和额外权限会作为提示回到 QQ；“同意”仅处理提示中的本次操作，不修改未来审批规则。

| 手机输入 | 用途 |
|---|---|
| `/py codex 帮助` | 使用说明，不消耗正在等待的输入 |
| `/py 状态` | 桥接任务是否运行、等待输入或已结束 |
| `/py 回复 桥接任务编号 内容` | 同时有多个任务时明确回答哪一个 |
| `/py 结果 桥接任务编号` | 查看桥接保留的最近最终答复 |
| `/py 详情 桥接任务编号` | 按需查看电脑保存的执行过程 |
| `/py 消息` | 按序号选择简洁或详细消息 |
| `/py 取消 桥接任务编号` | 停止该桥接任务及它启动的本轮 Codex 工作 |
| `/py codex 停止` | 选中 Codex 正在处理时，停止本次桥接任务 |
| `/py 回复 桥接任务编号 状态` | 查看原 Codex 会话最近保存的状态；不保证是另一个桌面进程的实时状态 |
| `/py 回复 桥接任务编号 结果` | 从 Codex 已保存历史读取最近答复 |
| `/py 回复 桥接任务编号 列表` | 切换目标会话 |
| `/py 4`（收到占用提示后） | 建立手机分支，并处理尚未提交的刚才要求 |
| `/py 重试`（收到桌面占用提示后） | 原连接释放后，明确重试尚未提交的原要求；必要时保存并退出占用它的桌面应用 |
| `/py 取消请求`（收到桌面占用提示后） | 丢弃尚未提交的原要求 |
| `/py 退出` | 结束 Codex 桥接，电脑会话历史保留 |

普通 `/py 内容` 在选中会话等待输入时交给它。操作指令“菜单”“状态”“结果”等仍优先由桥接处理；希望将它们作为内容时使用“回复 编号 内容”。

## 能做什么

- 继续已有项目对话，读取源码、分析问题、修改文件和运行验证，受 Codex 原有权限、项目指令和可用工具约束。
- 默认只发最终答复、必要确认、提问和错误。进度和中间说明保留在电脑，可按需查看详情或选择详细消息；结束对话不重播之前的回答。
- 回复确认、选项或补充信息。含隐私标记的输入只允许通过电脑面板提交，不经过 QQ。
- 取消只针对桥接启动的那一轮，已发生的写入和外部操作不能自动撤销。

## 当前连接方式与限制

本机接口使用官方 `codex app-server --stdio`，通过 JSON-RPC 调用 `account/read`、`thread/list`、`thread/read`、`thread/turns/list`、`model/list`、`thread/start`、`thread/fork`、`thread/resume`、`turn/start` 和 `turn/interrupt`。登录由 Codex 自己处理；桥接不读取、复制或发送 `auth.json`、登录令牌和密码。官方资料：[App Server](https://learn.chatgpt.com/docs/app-server)、[认证与登录缓存](https://learn.chatgpt.com/docs/auth)。

此连接是独立的本地 app-server 客户端，继续的是已保存的会话。此次电脑的桌面共享服务入口未能连接，因此**不保证桌面窗口实时刷新、运行状态完全同步，或复用桌面客户端的临时状态和专属工具**。桌面专属动态工具无法执行时会告知 Codex，不能假称执行成功。确认说明过长、无法完整展示时不授权执行。

同一个原会话仍需轮流操作。桌面应用即使没有生成答复，也可能保有 `active writer`，使独立 app-server 无法恢复该原会话。只读状态或最小化不是写入权释放的证明。新建独立聊天、手机分支或未被占用的其他会话可以在桌面保持打开时工作。

恢复会话遇到占用，或发现原会话仍在处理任务时，桥接保留尚未提交的要求。选“手机分支并处理刚才要求”才会建立分支并提交一次；选“重试”仍尝试原会话；“取消请求”丢弃要求。不会自动分支、迁移、归档或重复执行。分支只含已保存历史，无法复制桌面未保存草稿和进行中工具的临时状态。

本机可在 `.runtime/codex.json` 保存 `{"thread_id":"已有会话的完整UUID"}` 作为默认目标，仅保存编号。没有此文件时启动后显示列表。此配置和会话内容均不进入源码发布包。

从资源管理器双击启动时不再依赖 Codex 桌面进程提供的 PATH。每次启动连接时先查找已安装 CLI，再检查 Windows `%LOCALAPPDATA%/OpenAI/Codex/bin/*/codex.exe`，选择当前安装程序；目录随桌面更新变化时重新定位。显式指定的其他程序不存在时仍报错，不悄悄替换。未找到安装时给出具体说明，不要求重新填写 API Key。

当前只回传文字与进度，尚未为 Codex 单独增加项目附件自动收集。普通文件通道仍可处理共享目录的附件。当前账号的模型访问、使用限额及服务可用性仍由 Codex 提供。

本轮修复：Windows 没有显式代理环境变量时，Codex 子进程继承已配置的系统 HTTP/HTTPS 代理，回环地址直连，不修改系统设置；接口重连回传安全提示，桥接不重复提交要求。新建空会话首条消息不再被历史尚未 materialized 的错误拦住，其他历史查询错误仍正常报告。

## 验证范围

开发阶段在当前电脑验证本机 CLI（最初 0.163.0-alpha.11.2，更新后 0.164.0-alpha.11.1）握手、ChatGPT 登录状态、现有会话列表、选定本对话与等待交接。早期恢复原会话曾因 active writer 被拒，之后又发现 CLI 路径变化。0.8.2 自动定位修复后，清空 PATH 的真实握手、登录、列表，以及真实 QQ 指令进入编号交接提示均通过。占用后的保留、明确重试、取消待提交要求已用回归检查验证。

2026-10-25，用户明确补充“Codex 的读取文件返回文本我已经试过了，没问题”，并在区分继续已有会话/从 QQ 新建时回答“两种都试过”。据此将这两个方式的真实文件读取与文字返回记为用户确认通过；不冒称本轮维护者另行观察了具体模型、文件内容或截图，也不推定 Codex 项目写入、实际授权和取消等未报告分支通过。早期未启动模型的记录保留为历史失败，不覆盖这一最新实测结论。

随后本轮维护者实际复测：真实 QQ 恢复隔离测试会话并读取随机文件标记；拒绝后磁盘不变，同意一次后修正错误加法实现并通过只读测试。另按 QQ 项目/模型菜单选 gpt-6.1-sol 创建新会话，首问读取成功；命令开始后取消，35 秒后延迟写入的最终文件不存在。本段新增实测覆盖前段当时未复测的相应分支，不代表任意项目、全部模型或桌面专属工具均通过。
