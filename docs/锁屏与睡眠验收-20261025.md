# 锁屏、睡眠与保持唤醒

日期：2026-10-25。用户要求在发布前补做锁屏测试，并确认加入防自动睡眠功能。

## 使用方式

新版面板默认勾选“连接手机期间防止自动睡眠”。点击“连接手机”后，Windows 会收到只保持主机唤醒的临时请求；屏幕仍按原设置关闭，锁屏照常使用。点击“停止全部”或退出后解除请求，不修改系统电源计划。需要省电时，停止连接后取消勾选，再启动。仅“本机试用”不保持唤醒；旧单脚本入口不提供此开关。

这不会让程序在真正睡眠中运行，也不会自动唤醒电脑。手动睡眠、休眠、合盖、电量不足和系统管理策略仍可能暂停程序；远程工作期间应保持联网和供电。长时间监听会增加耗电。

## 锁屏实际验证

用户在电脑按 Win+L 锁屏。测试期间通过 Windows 会话接口观察锁定状态，没有模拟键鼠或解锁电脑。以下工作由中性测试指令经真实 QQ 后台回调执行，接收和发送检查均发生在锁屏期间：

| 工作 | 结果 |
|---|---|
| 计算 `17*19+5` | 任务完成，QQ 接受结果 `328`，内部接受回执没有额外发送 |
| Codex 手机分支 | 打开隔离测试会话选择、明确建立分支、调用真实模型，正确回答原历史中的随机测试编号；答复经 QQ 回传 |
| 文件报告 | 读取新建中性 TXT，生成“文件概览.txt”，QQ 后台返回上传凭据 |

测试完成后通知用户可以解锁。用户随后明确确认：“三项都收到，TXT 能打开”，包括计算结果、Codex 编号和报告中的“验收数字：328”。本次是实际锁屏与手机收件确认；不声称所有输入均由手机人工键入，也不外推到其他电脑、所有模型或所有文件格式。

本轮未补做锁屏下 API AI 与浏览器 ChatGPT 的实际模型请求；其此前后台测试不能替代锁屏专项证据。用户另报告“锁屏可以，睡眠不行”，与本机程序在睡眠期间暂停的边界一致。

## 防自动睡眠检查

新增五项检查覆盖临时请求只保持主机、不保持屏幕、在同一工作线程启用和释放、错误退出清理、关闭开关/本机试用不申请、旧设置兼容与开关保存、接口失败不假称启用。Windows 真实接口另确认请求注册及释放成功。面板连接生命周期覆盖正常停止和连接异常；没有修改空闲睡眠超时来冒充长时间待机验收。

实现使用 Windows 的 `SetThreadExecutionState(ES_CONTINUOUS | ES_SYSTEM_REQUIRED)`，退出时清除该线程的请求，不使用保持屏幕点亮或 away mode。[微软接口说明](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-setthreadexecutionstate)明确说明此接口无法阻止用户主动使电脑睡眠。

面板已重开加载此功能，电脑窗口可见勾选项和“已防止自动睡眠”日志，QQ 已重新连接。改进后完整 163 项回归通过（115.803 秒，Windows 本机无跳过）。
